# 第六步诊断：固定残差能保留多少新增成功

在第六步原 Linux 工作目录和 AUV 环境中运行。输入为 `outputs/chapter5/nominal_maddpg_pilot64` 中种子 2729 的原始检查点及验证记录。运行器使用 CPU 单线程，更新次数为零。

```bash
cd ~/AUV-Thesis/CH5-nominal-pilot
git fetch origin ch5-nominal-pilot
git merge --ff-only FETCH_HEAD
conda activate AUV
bash scripts/ch5_fixed_residual.sh check && bash scripts/ch5_fixed_residual.sh run
```

`check` 检查原试验身份、数据和归档摘要，计算并打印每艇固定向量。若原始 pilot 放在其他目录，给两个命令传入相同的 `--pilot-root /path/to/nominal_maddpg_pilot64`。结果默认保存在本项目的 `outputs/chapter5/audits/fixed_residual_2729_ep32/`。重复运行 `run` 会核对已提交的记录，从首个未提交场景继续。每完成一场会打印已完成场数、Actor 终局和固定残差终局。

## 对照设计

- 冻结种子 2729 第 32 回合的在线 Actor。取该边界 Replay 中全部 10,351 个训练团队步。对每艘艇，只在其执行门开放的本艇局部观测上重新计算确定性 Actor 输出，将三个带符号分量各自取算术平均。累加使用 float64，交给运行器时采用 float32。每个开放决策等权。原 Replay 的探索动作、后续回合与验证场景均不参与拟合。
- 固定策略每个决策步向每艇提供相同的三维归一化残差。原有执行门、限幅、不同角色的残差比例、声呐、A*、通信、物理、奖励和原终止条件继续生效。每步核对实际执行动作与固定向量经原生执行门后的值。
- 复用同一组 32 个验证场景的初始化和第 32 回合 Actor 归档。先用冻结 Actor 在场景 7200004 做一次完整复现，要求终局、步数、发现、交接、接触步数及收发位数与原记录逐字段相等。累计回报采用绝对容差 0.0000001，并保存实际差值。原档保存的是回合级字段。复现失败时报告首个超出标准的字段及两侧值，固定策略比较停止。
- 通过复现后，固定残差在这 32 个场景各跑一次，每场使用原场景种子、原验证索引和派生信道种子。总预算为 1 个 Actor 复现回合和 32 个固定残差回合。

## 结果口径

`run.json` 保存四艇三轴固定值、开放样本数、各轴离散程度、代码和运行身份。`fixed/scene_*.json` 是逐场终局记录。`report.json` 列出三组成功、碰撞、超时、平均原任务回报、完整配对结局及单侧成功的场景编号。

首要读数是初始化失败、第 32 回合 Actor 成功的 4 场中，固定残差还能完成几场。保住 3–4 场记为复现多数，2 场记为一半，0–1 场记为少数。同时看 32 场中只有 Actor 成功、只有固定残差成功的场景，以及碰撞和超时的转移。固定残差可能在不同场景获得相同成功总数，也可能保住新增成功却丢失原有成功。

这是一项对已选检查点、已看过的开发验证集和一种训练分布均值策略的事后机制诊断。结果评价这个固定策略的替代能力；均值策略失利时，其他常量、分阶段规则或更简单的状态反馈仍是竞争解释。本试验的结果独立于三种子学习准入条件。
