# 第五章 v3：以可训练通信网络为核心

日期：2026-11-13。接入更新：两个网络已接入真实任务、数据标签与有限RL训练，并完成短流程；**正式性能仍未验证**。最新状态及实现边界以 [工程说明](CH5_INTEGRATION_20261113.md) 和 [短测结果](CH5_SHORT_TEST_RESULTS_20261113.md) 为准。下文保留最初网络蓝图，其中“尚未接入”的描述属于原型阶段。全目标、队友、地图及控制通信受限的范围保持。

## 1. 对上一版定位的修正

上一版主要解决“谁能知道什么、迟到证据怎样处理、预算如何一致”。这些是必要基础，但不足以成为本章主要网络创新。v3将主线转为：**发送端学习保留哪些任务信息，接收端学习怎样在地图条件下推进迟到的动态表征**。协议、源追踪、预算mask和风险准则降为支撑，不再靠手工阶段评分组织主方法。

当前新增的原型位于 `chapter5_comm/neural_modules.py`。其中两个主网络、一个任务辅助头和一个标准发包策略头均有实际PyTorch参数与可微损失接口。原型能够做前向/反向，不代表已经形成完整的任务训练系统。

## 2. 核心网络A：任务查询条件的双流压缩编码器

类：`TaskPacketEncoder`。

输入分为：

- 地图patch tokens：位置、局部占据/未知表示与路径相关几何特征；来自本艇合法地图。
- 动态tokens：本艇已知目标/队友的状态、预测与不确定性；不是全队实时真值。
- 接收者任务查询：实际收到的请求，后续可编码第三章候选路径、预计到达时刻与所需信息；未收到时使用可学习unknown查询。

两流分别以可学习slot query做交叉注意力压缩，输出固定个数packet latent。原型默认latent维32、地图2包、动态2包，可作为起点比较。输出采用固定8位有界量化，训练用STE；payload位数按真实int8元素计算，另加显式声明的包头长度。完整帧、请求/ACK和信道计费尚待接入，不能把原型budget接口说成实物通信验收。

**本模块不使用“交接阶段加1.5”之类人工消息评分。** 信息压缩的学习目标是：收到有限packet后，接收端仍能判断哪些候选路径可能与移动目标相遇。

### 任务结构监督

辅助 `RouteUtilityHead` 从解码的地图与动态上下文，加第三章候选路径特征，输出每路线logit。主监督接口是：

\[
L_{enc}=\operatorname{BCEWithLogits}(\hat p_{\ell},y^{enc}_{\ell}).
\]

后续标签提供器可由记录的未来目标轨迹与候选AUV执行预测，构造相同物理预测时刻下的相遇标签。它是几何/有限模型近似监督，不是精确完整任务反事实回报。数据生成器本轮未实现，不能伪造teacher或用最终测试轨迹训练。

另提供 `route_distillation_loss` 接收外部teacher logits并计算带候选mask的KL；teacher必须另行建立和核验。该接口存在不代表本项目已有可信teacher。

辅助头的目的，是让encoder/decoder的梯度保留路线判断信息；它不是已经替换第三章规划器的新路线策略。编码器本身的attention、query与量化均为已有工具，创新候选在任务查询保真与后述地图条件时间解码的耦合。

## 3. 核心网络B：几何条件的连续时间动态解码器

类：`GeometryTemporalDecoder`。

输入为实际收到的量化packet、packet类型/年龄、本艇地图上下文。输出包括地图latent、当前动态latent、状态分布的mean/log-variance，以及是否收到对应类型信息的标记。

静态地图流不进行运动外推；动态流使用显式依赖地图的可学习向量场：

\[
z_{k+1}=z_k+\delta t\,f_\theta(z_k,G,z_k\odot G).
\]

原型以固定步数Euler积分实现时间运输。零年龄为identity；几何G直接进入运动更新，而非只在网络末尾拼接。要学习的现象例如：同样的目标速度和信息年龄，在开阔区与可能反射/受阻的地图条件下，其未来状态分布不同。原型尚未学到这些现象，不宣称随机初始化即满足真实运动规律。

两种辅助约束：

\[
L_{pred}=-\log p_\theta(x_{t+\Delta}\mid z_t,G,\Delta),
\]

\[
L_{time}=\|F(F(z,\Delta_1;G),\Delta_2;G)-F(z,\Delta_1+\Delta_2;G)\|^2.
\]

时间组合损失只用于地图条件固定、期间没有新信息的区间；它是训练约束，不是已经证明的精确半群性质。必须同时有预测/任务监督，防止identity退化解。方差输出是可训练估计，不是安全保证。

丢弃的payload、未知query和未送达消息必须在网络计算前屏蔽，包括NaN或任意隐藏值。全缺包时输出只有本地上下文与先验预测，并显式标记没有动态/地图包；不能把预测当真实观测，也不能用网络结果直接覆盖具有事实来源的占据证据。

## 4. 标准网络C：预算条件发包策略

类：`BudgetedPacketScheduler`。

输入为候选packet、合法本地context、每包位数、剩余预算和候选有效性。网络输出消息选择或NOOP的Categorical分布。logit由网络产生，无人工阶段加分。预算mask负责不可行选择，NOOP始终合法。

原型一次选择一个包；多包顺序选择须在运行时更新剩余预算、去除已选包并重算分布。它不等于已实现完整TDMA、跨艇仲裁或网络协议。请求、ACK和下行同样必须计费；发送端不能读取接收者实时belief。

此头是标准RL接口，不因为多写一层MLP就列独立原创。网络A与B及其任务耦合是主要研究对象。

## 5. 训练闭环及当前缺口

建议顺序：

1. 接入合法数据提供器，按训练/验证/测试隔离采集地图、动态、消息和候选执行轨迹。对丢包、burst、延迟和乱序做一致的数据增强。
2. 用 \(L_{pred}+\lambda_rL_{enc}+\lambda_tL_{time}\) 训练A/B。系数在验证集选择；损失可微不等于梯度已经由任务环境产生。
3. 选定第三章后端，增加明确的decoded-context适配器；在固定通信下建立共同任务Actor，再冻结A/B和任务Actor，训练发包策略头。
4. 如需联合RL，另实现可微task adapter、对应critic/联合目标和版本化数据。非可微规划器不会自动把任务回报梯度传到decoder。后续交替微调与CVaR仍为可选研究项。

本次实现网络和损失原型，没有实现上述数据提供器、第三章适配器、信道、on-policy learner、任务训练或checkpoint。合成张量的backward仅验证计算图。

## 6. 必要消融：证明模块设计有用

| 假设 | 直接对照 |
|---|---|
| 压缩保留了任务决策所需信息 | 同字节普通池化/autoencoder；只重建观测；加相遇/路线损失 |
| query有实际作用 | 收到的真实任务查询、unknown查询、接收者角色查询；query传输成本相同计入 |
| 两流之间有特殊耦合 | 双流最终concat，对比地图条件动态transport；保持容量/计算量可比 |
| 时间运输优于单纯遗忘 | 末状态、年龄衰减、固定运动外推、可学习transport |
| 一致性约束有用 | 仅NLL，对比NLL＋时间组合；同时检查预测误差和任务收益 |
| 学习发包优于手工评分 | 相同codec/decoder下的固定发送、人工阶段规则与学习头 |

核心比较要包含近期近邻：CACOM已有接收者上下文条件编码，CoDe已有意图/时效融合，VA-MARO已有价值感知预测；2026 latent exploration已有地图autoencoder＋RL。因此不能把“attention、RNN、latent map、age或query”单独称首创。[CACOM官方论文](https://www.ifaamas.org/Proceedings/aamas2024/pdfs/p1156.pdf)、[CoDe](https://arxiv.org/abs/2501.05207)、[VA-MARO](https://arxiv.org/abs/2607.17914)、[latent exploration](https://arxiv.org/abs/2601.01139)。
