## 已有工作如何评价

1. **阶段VOI：有任务结构价值，当前仍以启发式为主。** `comm/voi_selector.py:228` 有固定阶段加分；`:280` 合并消息与链路代价。不能直接称为下游任务价值最优调度。
2. **历史预测：有实用价值，不必是神经网络才有贡献。** `comm/teammate_predictor.py:135` 是恒速外推加意图拉动、消息年龄与不确定性修正。要成为主要创新，需有新的状态维护组织、误差性质或明确任务收益机制，而不仅是启用外推。
3. **SafeGate：已经让通信质量影响策略动作，具有RL接入内容。** `utils/safe_channel_gate.py:653` 为base action加入门控适配；但注意力、门控和残差是通用构件，需要明确面向过期信息/交接风险的特殊构造和独立增益。命名Safe不等于已有安全保证。
4. **复杂扩展暂不列主创新。** 现存ERHGC批次 full四工况均值36.25%，父hint39.25%，去event仍36.25%；ECHB full39.0%，父hint39.25%。这是特定批次，不能证明所有配置无效，也不足支持稳定优势。

## 最新ICR怎样形成足够实质的贡献

- **核心学习机制**：交接关键任务价值驱动的消息选择与策略协同。给出消息价值的实际估计方法、合法输入、训练信号、发送决策与接收动作接口；用人工阶段评分作直接对照。
- **鲁棒训练机制**：明确通信集合、风险聚合/最坏分布更新和策略优化。普通故障随机化不能仅改名为DRO，四工况均值也不是最坏分布性能。
- **接收因果状态作为有效性基础**：处理时间戳、乱序、过期和来源，消除未收包执行者读取目标cache的影响。正确性本身不足单独撑起主要算法创新；具体异步估计方法及误差到任务损失的性质可进一步贡献。

建议先形成“核心学习机制＋鲁棒训练机制”，把消息协议、预测与门控作为支撑，不继续扩张未经验证的拓扑模块。理论先完成一个有内容且假设清楚的性质，不预先承诺多个未证实的最优性界。

## 实验充分性

现存381评价表含268份100回合表和113份2回合smoke，不是381次独立训练。另有4000回合主训练记录。历史5.4/5.5有24原始表缺失，40.5%对33.0%只能作为汇总提升线索，不能在本项目重命名为已复核结果。当前静态可达的全局目标cache→未知执行者fallback会在“目标仅经受限通信”假设下产生旁路，需先明确权限。

必要支撑：相同底座/任务/预算/故障训练的公平基线；关键模块重新训练消融；独立训练种子；训练外信道；纯通信与物理扰动拆分；任务成功之外的交接、状态误差、消息年龄与通信成本；原始逐回合表到代码、配置、checkpoint和场景清单的完整来源链。
